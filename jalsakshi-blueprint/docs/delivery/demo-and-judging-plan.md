# Demonstration and judging plan

The event listing emphasizes project-to-product qualities. The mapping below uses its stated themes; **weights are not verified and no win is guaranteed**. Eligibility/deadlines are in [assumptions](../assumptions-and-open-questions.md).

## The demonstration story

A school/campus water source has a screening result requiring review. A worker records it without connectivity. The record survives restart and synchronizes without duplication. A supervisor receives one owned case, sees a lab-confirmation boundary and cannot close it without the required proof. After a clearly simulated lab/action/retest sequence, closure evidence and resident communication are visible.

The judge should remember **a record that survives disconnection, refuses false certainty and cannot disappear into an unowned handoff**.

## Five-minute script

| Time | Action | Evidence / disclosure |
|---|---|---|
| 0:00–0:35 | Explain one source and one person responsible for follow-up | No sweeping “all systems fail” assertion |
| 0:35–1:30 | Airplane mode; source QR; protocol; capture/manual fallback | Use actual supported kit or visibly synthetic fixture; acknowledge chemical read time rather than fast-forward as real |
| 1:30–2:00 | Deliberately bad capture → retake/uncertain | Shows refusal to guess; model version visible |
| 2:00–2:35 | Save, force stop/reopen; reconnect and replay | Local/server record IDs/counts prove persistence and no duplicate case |
| 2:35–3:45 | Supervisor assign/referral; attempt invalid closure | Server rejects missing evidence; lab report is explicitly synthetic for demo |
| 3:45–4:25 | Link simulated verified report/action/retest/update; close | Walk timeline; no live lab claim |
| 4:25–5:00 | Show measured latency/quality evidence if available, limitations and pilot request | If unmeasured show planned experiment, not an invented chart |

If the actual event pitch time differs, shorten explanation, not truthfulness. Chemistry timer may be demonstrated using a recorded compliant capture labeled replay; do not imply the reaction occurs instantly.

## Rubric mapping

| Criterion | What to show | Evidence expected |
|---|---|---|
| Problem relevance / impact | Named target user and handoff job | Interview/baseline notes, bounded official context |
| Innovation | Protocol/uncertainty/evidence-loop integration | Honest Akvo/mWater/ODK comparison, no global novelty |
| Technical execution | Native local pipeline + durable sync + version guards | Real-device inference/persistence and server negative tests |
| Functionality | Complete field-to-closure loop | IDs, timestamps, receipts and proof checklist |
| User experience | Few clear steps, manual recovery, local language | User task observations/a11y checks |
| Feasibility | One supported kit/domain and measured constraints | Dependency proof, test set independence and explicit remaining work |
| Scalability / startup potential | Configurable protocol plus actual buyer hypothesis | Second-kit plan, capacity/cost assumptions, no fake traction |
| Presentation | One coherent live story | Working build, concise source-linked backup evidence |

## Demo evidence pack and backup

Prepare exact APK/server build hashes, supported phone/kit list, model card, small anonymized/synthetic dataset manifest, offline/replay video, failure-case clip, measured timing CSV if available and one-page limitations. A prerecorded run is backup evidence, not presented as live.

If network fails: demonstrate true local durability and show an explicitly prerecorded sync segment. If camera fails: use manual workflow and explain automation failure. If AI is unfinished: show the deterministic baseline clearly labeled and explain model-validation task; never fabricate a result.

Synthetic lab reports should carry a large “DEMONSTRATION — NOT A LAB RESULT” watermark. Generated concept visuals must be labeled; do not use them as product screenshots or experimental evidence.

## Claims to remove from the pitch

“99% accurate,” “detects all contamination,” “guarantees safe drinking water,” “first-ever offline AI,” “already integrated with WQMIS,” “zero latency,” “unlimited scale,” “no image ever leaves the phone” when upload enabled, and any promised incubation/funding outcome unsupported by organizer terms.

## Final rehearsal checks

Two independent cold starts; airplane-mode persistence; duplicate retry; bad-image refusal; wrong-role denial; blocked invalid closure; accessible fallback; synthetic/live labels; receipt IDs consistent; lab/report source provenance; no personal data/secrets visible; backup power/APK/video available.
